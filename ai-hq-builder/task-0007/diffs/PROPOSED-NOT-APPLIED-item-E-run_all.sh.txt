`51_` item E requires `poc/harness/run_all.sh` to distinguish "an optional
dependency was unavailable, so this check did not run" from "this check ran and
failed", and to make the exit status reflect that distinction.

`poc/harness/run_all.sh` is on the **immutable denylist**. `25_` §0 names it
explicitly — "all `poc/harness/*.py`, `*.mjs`, `run_all.sh`" — and `51_` §3 and
§5 both restate that denylist unchanged. `51_` §2 item E therefore requires a
change to a file the same packet forbids changing. Every file in the chain item E
names (`run_all.sh`, `validate_n8n_workflows.mjs`, `selftest_validator.mjs`) is
denylisted, so there is no allowlisted seam through which the behaviour could be
reached instead, and no new-file route: `51_` §5 permits new modules under
`stub/`, and nothing under `stub/` can change what `run_all.sh` prints.

`51_` §5 says to stop and report when a clause is internally inconsistent. Item E
is explicitly non-gating, so the round is not stopped — only item E is. This is
the patch, unapplied, so that authorising it costs one line.

VERIFIED, without applying it: the patched script was run from `poc/harness/`
under a temporary name, with `n8n-workflow` absent and then present, and the
temporary copy deleted afterwards.

    dependency ABSENT   exit 2   === HARNESS INCOMPLETE (every check that ran

The patch is exit-status-preserving for every check that actually runs: `fail` is
still set by any real failure and still exits 1. Only the
skipped-because-unavailable case changes, from FAIL/1 to INCOMPLETE/2. No
vendoring, no network requirement — `51_` item E forbids both and this adds
neither.
